I. Giới thiệu

Design pattern một khái niệm được lặp đi lặp lại khi chúng ta code. Chúng ta đều đã nghe nhiều về những mô hình này, nhưng thực sự chúng là gì?

Chúng là những mô hình lý thuyết phù hợp để giải quyết được một vấn đề cụ thể.

Trong các phần sau của bài viết, các pattern thông dụng sẽ được trình bày với C++.

II. Prototype

Định nghĩa: một prototype là một class với mục đích để được clone.

II.1. Ví dụ tác dụng của prototype

Trong quá trình viết các chương trình, bạn sẽ phải khởi tạo các object với kích thước nhất quán trong bộ nhớ.

Tạo một object lớn sẽ không có vấn đề gì. Nhưng tạo nhiều object cùng lúc sẽ có thể hủy hoại hiệu năng chương trình của bạn.

Giải pháp là sao chép base object, prototype, để chỉnh sửa những đáp ứng cần thiết cho object mới.

Một cách sử dụng khác là khả năng cho phép clone để nhân đôi các object poly-morph. Trên thực tế, để sử dụng copy constructor, cần phải biết rõ kiểu của object, điều không tồn tại khi chúng ta sử dụng dynamic polymorphic trong C++.

Với phương pháp này, chúng ta nhận ra rằng pattern prototype có một method bắt buộc, Clone, và một tùy chọn Change. Cái đầu tiên là để thực hiện một copy prototype trong khi cái thứ hai có vai trò thay đổi trạng thái của object.

II.2. Ví dụ áp dụng sơ cấp

Sau phân tích ở trên và lấy ví dụ với một kết nối MySQL, áp dụng đầu tiên đối với pattern này có thể đơn giản như sau:

std::auto_ptr<MySQLManager> MySQLManager::Clone() const
{
    return std::auto_ptr<MySQLManager>(new MySQLManager(*this));
}

int main(void)
{
//main ne change pas, on est juste sûr que la mémoire sera libérée en cas de problème
}

//file prototype.h

#ifndef PROTOTYPE_H
#define PROTOTYPE_H

#include <string>

class Prototype
{
  public:
  virtual ~Prototype();
  virtual Prototype* Clone() const = 0;
};

class MySQLManager: public Prototype
{
  std::string m_host,m_login,m_pass;
  std::string m_base,m_table;
  public:
  MySQLManager(const std::string& host="",
               const std::string& login="",
               const std::string& pass="");
  MySQLManager* Clone() const;

  void Afficher();
  void Set(const std::string& base="",const std::string& table="");
};

#endif

//fichier prototypetpl.h

#ifndef PROTOTYPE_H
#define PROTOTYPE_H

#include <string>
#include <memory>

template <class T> class Prototype
{
public:
    virtual ~Prototype(){}
    virtual std::auto_ptr<T> Clone() const =0 ;
};

class MySQLManager: public Prototype<MySQLManager>
{

    std::string m_host,m_login,m_pass;
    std::string m_base,m_table;

    MySQLManager(const std::string host="",const std::string login="",const std::string pass="");

    void Afficher() const ;
    std::auto_ptr<MySQLManager> Clone() const ;
    void Set(const std::string base="",const std::string table="");
};

#endif

Class này được thực hiện tức thời bằng cách xác định method Clone. Nhưng virtual function Prototype::Clone trả lại một Prototype. Chúng ta biết rằng kiểu trả về không phù hợp với định nghĩa của function. Trình biên dịch trên lý thuyết sẽ không bằng lòng với điều này.

Nhưng thực tế nó được thực thi trơn tru bởi  vì các giá trị trả về co-variance (cùng kiểu).
Để đơn giản, các giá trị trả về co-variance trong trường hợp mà giá trị trả về của một virtual function là một reference hoặc một con trỏ đến một class C. Do đó các class tái định nghĩa virtual function này có thể gửi lại một con trỏ hoặc một reference đến một class bắt nguồn từ C.

Đó là những gì diễn ra ở đây. MySQLManager bắt đầu từ Prototype nên MySQLManager::Clone có thể trả về một con trỏ tới một instance của MySQLManager.

Nhưng vấn đề ở đây là Clone trả về một con trỏ thô, sử dụng một con trỏ thông minh để xử lý nó không bắt buộc chút nào. Nếu người dùng sử dụng một con trỏ thô để quản lý bộ nhớ, điều này có thể gây ra sự cố để khôi phục bộ nhớ trong trường hợp ngoại lệ.

Nhưng vấn đề ở đây là Clone trả về một con trỏ thường, sử dụng một con trỏ thông minh để xử lý không bị bắt buộc. Nếu người dùng sử dụng một con trỏ thường để quản lý bộ nhớ, điều này có thể gây ra sự cố khi khôi phục bộ nhớ trong trường hợp hi hữu.
